before the next phase starts.

## Phase 2 — Rule catalog (50 rules)

**Deliverables**
- All 50 rule files in `/rules/` following the exact template in PRD §4.2
- Every rule cites sources from PRD §4.3 (Neodyme, Sec3, Helius, Anchor book, Cyfrin, public audits) — no invented content
- `rules/INDEX.md` table: ID, name, severity, category
- `rules/README.md` explaining the template and contribution rules
- `SKILL.md` body filled in: workflow, rule catalog links, output format, limitations

**Process:** batches of ~10 rules (matching the PRD categories), review each batch before the next.

**Checkpoint 2 — ✅ passed 2026-06-10** (enforced by `tests/rules.test.ts`, 253 assertions)
- [x] 50 files exist, names match PRD §4.1 exactly
- [x] Each file has all 7 template sections and ≥2 references
- [x] `INDEX.md` row count = 50, severities assigned (4 Critical / 21 High / 17 Medium / 8 Low)
- [x] `SKILL.md` 90 lines (< 600) and links to every rule

## Phase 4 — CLI implementation

**Deliverables**
- `scanner.ts`: collect/filter `.rs` files under target path, validate Anchor layout
- `rules-loader.ts`: load `/rules/*.md` from the installed package, parse ID/severity/category
- `auditor.ts`: Claude API orchestration — rules batched 4–6 per call, structured JSON findings, model `claude-sonnet-4-6` default
- `reporter.ts`: markdown (PRD §5 format) + JSON output, severity sorting, exit code 1 on critical/high
- All flags: `--output`, `--rules`, `--severity`, `--format`, `--verbose`, `--api-key`, `--model`
- Unit tests against `tests/fixtures/` snippets; documented JSON schema for findings

**Checkpoint 4**
- [ ] `npm install -g .` works; `anchor-audit examples/01-vulnerable-vault` produces a report
- [ ] Findings match `EXPECTED_FINDINGS.md` (iterate on prompts until they do)
- [ ] JSON output validates against the documented schema
- [ ] CI green
